# In-Game World Map with Quest Regions Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the quest board's home a pannable BlueMap-tiled map of the current dimension with each located quest drawn as a polygon, and let the editor set a quest's location by drawing that polygon on the same map.

**Architecture:** Protocol V2 adds a `polygon` vertex list to quests (server keeps the legacy point/rectangle columns in sync so 0.5.x clients keep working). The client gets a `MapView` owo component that draws BlueMap lowres tiles from a `TileCache` (async fetch, LRU textures, disk cache) and stacks `MapLayer`s on top (quest polygons, player marker, polygon editor). `MainScreen` becomes map + side list; `QuestScreen` gets a location card and a full-screen `MapEditScreen`.

**Tech Stack:** Java 25, Minecraft 26.3 / Fabric, owo-lib 0.13.1+26.3 (vendored), Paper 26.3, SQLite, JDK `HttpClient`, JUnit 5, Mockito (server), Fabric client gametest harness (E2E).

**Spec:** `docs/superpowers/specs/2026-11-06-world-map-design.md`

**Branch:** `feat/world-map`, created from `design/images-and-map` (the only branch holding the spec). Never push to main.

## Global Constraints

- Polygon: 1 to 64 vertices of `(double x, double z)` block coordinates, implicitly closed, simple (no self-intersection). Y is not stored for polygons; a pin keeps `x, y, z`.
- Canonical dimension keys: `overworld`, `the_nether`, `the_end`. `nether` → `the_nether`, `end` → `the_end` are accepted and normalised everywhere (config lookup, save, migration).
- A located quest in V2 always has a dimension (editor defaults to the one the player stands in).
- New packet fields are trailing-optional; never insert mid-packet. `ProtocolVersion.CURRENT` becomes `V2`.
- HTTP: https only unless the JVM property `disquests.test.allowHttp` is `true`; 10 s timeout; 2 MiB per tile cap; content type must be `image/png`.
- Tiles: `<bluemap-url>/maps/<mapId>/tiles/<lod>/x<X>/z<Z>.png`. Defaults when `settings.json` is unavailable: `tileSize 500`, `lodFactor 5`, `lodCount 3`. A lod-N tile covers `500 * 5^(N-1)` blocks; tile index = `floor(block / coverage)`. PNG is 501×1002: draw only the top-left 500×500 (the 501st px is overlap).
- Zoom: zoom 0 = lod 3 (25 blocks/px), 1 = lod 2 (5), 2 = lod 1 (1), 3 = lod 1 drawn at 0.5 blocks/px. Default on open: zoom 2, centred on the player. Scroll zooms around the cursor; middle-drag pans.
- World limits: tiles entirely outside ±5000 blocks (overworld, the_end) or ±1250 (the_nether) are not requested.
- Texture cache: max 256 tile textures (LRU, release on evict), 404/failed tiles memoised per session, in-flight dedup, 2 fetch threads, texture upload on the render thread, disk cache in `<gameDirectory>/disquests/tiles/` honouring `max-age` (default 86400 s).
- Mouse buttons: compare only against `InputConstants.MOUSE_BUTTON_LEFT/MIDDLE/RIGHT`, never literals (SDL3 numbering).
- Polygon style: fill 25 % alpha, 1 px outline; open quests amber, closed quests grey, private quests amber; own quests get a second brighter outline; hover fill 45 % plus tooltip (title, owner). Overlapping polygons: smallest area wins the click. Pins: 7 px marker.
- Formatting: `./gradlew spotlessApply` before every commit (lefthook does it for staged files).
- Lang: every new user-facing string goes in `en_us.json5` and `fr_fr.json5` (French informal "tu", accents required, gaming terms stay English).

## Review Focus

1. SAVE_QUEST with more than 64 vertices, or NaN/infinite coordinates: the server must drop the packet with a warning, never persist it. (Pinned in Task 6.)
2. A 0.5.x (V1) client that re-saves a polygon quest without touching the rectangle must not flatten the polygon to its bounding box. (Pinned in Task 6.)
3. A quest dimension with no BlueMap map id (custom dimension, or `bluemap-url` empty): the map draws the grid and polygons, requests nothing, shows the notice. (Pinned in Task 10.)
4. A tile response that is not a PNG, is over 2 MiB, or whose body fails to decode must become `MISSING`, never a crash or a retry storm. (Pinned in Task 10.)
5. Scrolling past the zoom bounds must clamp and keep the block under the cursor fixed, including at window edges. (Pinned in Task 8.)

### Task 3: PacketCodec V2

**Files:**
- Modify: `common/src/main/java/com/disqt/disquests/common/PacketCodec.java`
- Test: `common/src/test/java/com/disqt/disquests/common/PacketCodecTest.java`

**Interfaces:**
- Consumes: `QuestData.polygon`, `QuestLocation.normalize`, `ProtocolVersion.V2`.
- Produces: `writeQuest(ByteBufWriter, QuestData, int protocolVersion)`: for `protocolVersion >= V2` append `varint count` then per vertex two raw-long doubles `(x, z)` after the tags; for `< V2` write `QuestLocation.normalize(quest)` legacy fields and no polygon.
- Produces: `QuestData readQuest(ByteBufReader buf, int protocolVersion)`: reads the polygon block only when `protocolVersion >= V2` (count bounded by `QuestLocation.MAX_VERTICES` via `readCount`). `readQuest(buf)` = `readQuest(buf, ProtocolVersion.CURRENT)`. Same `protocolVersion` overloads for `readSyncMyQuests`, `readSyncServerQuests`, `readUpdateQuest`, `readCollaborationResponse` (the no-version overloads stay and mean CURRENT).
- Produces: `SaveQuestPayload` gains trailing `List<PointData> polygon`; `writeSaveQuest(..., List<String> tags, List<PointData> polygon)` appends the polygon block; `readSaveQuest` reads it when `buf.remaining() > 0`, else `List.of()`. Keep the old 8-arg `writeSaveQuest` delegating with `List.of()`.
- Produces: `HandshakePayload` gains trailing `int serverProtocolVersion` (`ProtocolVersion.V1` when the field is absent). Every `writeHandshake` overload now writes the full form: tags, default map, then `varint ProtocolVersion.CURRENT`. The existing `int protocolVersion` parameter no longer gates anything (keep it for source compatibility, document it as ignored). `readHandshake` reads the trailing version when `remaining() > 0`.

Rationale recorded for the implementer: the server sends the handshake at join before it knows the client version, so gating on the player's version meant V1 clients never received tags or the default map. A V1 client's `readHandshake` stops after the default map and ignores trailing bytes, so always writing the full form plus the version is safe.
